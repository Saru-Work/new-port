    (06) How I work
    
          
    01 / 04
    
        
    
        
    
          
    
            01
            
    Understand the problem.
    
            
    Who's it for, what hurts today, and what does “working” look like? Requirements first, code second.
    
          
    
          
    
            02
            
    Design the solution.
    
            
    Data model, API contracts and architecture on paper — with the trade-offs written down, not discovered in production.
    
          
    
          
    
            03
            
    Engineer it.
    
            
    Typed, tested, containerised and documented. Code someone else can pick up and run on day one.
    
          
    
          
    
            04
            
    Improve it.
    
            
    Measure, profile, refactor, repeat. Every version should be faster, clearer or more reliable than the last.
